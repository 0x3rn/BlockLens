# BlockLens

BlockLens is a focused crypto market tool built with React, TypeScript, and Vite. It combines live CoinGecko spot-market data with precise price formatting, historical charts, asset comparison, device-local portfolio tracking, threshold alerts, and opt-in scenario-based AI research.

BlockLens is educational software, not a brokerage or financial adviser. Market data can be delayed, local alerts only run while the site is open, and AI briefs can be incomplete or wrong.

## What is implemented

- Global market capitalization, 24-hour spot volume, market-cap movement, Bitcoin dominance, active assets, and tracked exchanges from CoinGecko.
- Searchable, filterable, sortable top-100 market table with adaptive precision for micro-priced assets and pagination.
- Asset profiles with 7-day, 30-day, and 1-year price history; volume, SMA-20, and logarithmic chart controls; supply and market statistics.
- Trending assets and current 24-hour gainers/losers.
- Comparison of up to four assets using normalized “growth of 100” performance.
- A watchlist, portfolio quantities, cost basis, unrealized P&L, and CSV import/export. Signed-in users can sync these privately across devices; signed-out users remain device-local.
- Email/password accounts backed by Supabase Auth with a private, row-level-secured portfolio schema.
- Price and 24-hour movement alerts evaluated during the 60-second refresh while BlockLens is open.
- On-demand AI trading analysis generated by a serverless function. API credentials never ship to the browser, and output includes a conditional LONG, SHORT, or NO TRADE setup with entry, stop, targets, risk/reward, invalidation, and bullish/base/bearish scenarios. Generated briefs are saved in History for later review.
- Telegram AI analysis bot integration. `/ai-analysis` opens the current top-100 market list in a paginated inline keyboard; selecting a coin fetches a fresh snapshot and returns the same validated Gemini brief used by the website.
- History for previous AI briefs and portfolio position activity. Signed-in users sync both history streams through Supabase; signed-out users keep them in this browser.
- A paper-futures simulator with live Binance mark prices, virtual margin, leverage, liquidation protection, stop-loss/take-profit exits, and simulated execution history. It never submits exchange orders.
- URL-based navigation, route-level code splitting, a 404 page, resilient loading/error states, responsive navigation, keyboard focus styles, and reduced-motion support.
- Vercel Analytics and deployment security headers.

## Local development

Requirements: Node.js 20.19 or newer and npm.

```bash
npm install
npm run dev
```

Vite prints the local URL, normally `http://localhost:5173`.

Other commands:

```bash
npm test          # run the test suite once
npm run test:watch
npm run build     # type-check and create dist/
npm run preview   # serve the production build locally
```

## AI configuration

Copy `.env.example` to `.env.local` for a local serverless environment, or configure the variables in the deployment platform:

```env
GOOGLE_CLOUD_PROJECT=your-google-cloud-project
GOOGLE_SERVICE_ACCOUNT_JSON={"type":"service_account",...}
```

For account sync, also add the client-safe Supabase values:

```env
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-key
```

Run `supabase/migrations/0001_blocklens_accounts.sql` and then `supabase/migrations/0002_blocklens_history.sql` in the Supabase SQL editor. Keep **Automatically expose new tables** disabled and enable automatic RLS. The migrations enable RLS, create per-user policies, and grant access only to the `authenticated` role. Never expose a Supabase service-role key to the browser.

These variables intentionally have no `VITE_` prefix. The service-account JSON remains server-only. BlockLens obtains a short-lived Google Cloud access token and calls `google/gemini-3.1-pro-preview` through Vertex AI's OpenAI-compatible endpoint. The prior DeepSeek client is retained only as commented code, matching the Vera integration.

The Vite development server includes local adapters for `/api/analyze` and the Telegram routes. Telegram still needs a public HTTPS tunnel or preview URL before Telegram can deliver webhook updates.

## Cloudflare Workers deployment

This repository can be deployed to either Vercel or Cloudflare Workers from the same commit. The Worker entrypoint is `worker/index.ts`; it serves the Vite build in `dist/` through the `ASSETS` binding and handles the dynamic API routes. Vercel continues using the handlers in `api/`. The market, AI, and Telegram logic is shared under `api/`.

In Cloudflare Workers Builds, use the repository root (`/`), set the build command to `npm run build`, the deploy command to `npx wrangler deploy`, and the non-production version command to `npx wrangler versions upload`. The checked-in `wrangler.jsonc` configures `dist/` as Worker static assets, sends `/api/*` requests to the Worker first, and falls back to `index.html` for client-side routes.

Add the server values as encrypted environment variables for both preview and production:

```env
GOOGLE_CLOUD_PROJECT=your-google-cloud-project
GOOGLE_SERVICE_ACCOUNT_JSON={"type":"service_account",...}
# Optional; leave both unset for the keyless public API
# COINGECKO_API_KEY=your-coingecko-key
# COINGECKO_API_PLAN=demo
TELEGRAM_BOT_TOKEN=your-bot-token
TELEGRAM_WEBHOOK_SECRET=a-long-random-secret
```

The Worker uses the Web Crypto API for Vertex AI service-account authentication, so it does not depend on the Node Google Auth client at runtime. The Worker route handler is kept separate from Vercel’s adapter, while the validation, market-data, Telegram, and AI modules remain shared.

`COINGECKO_API_PLAN` is `demo` for a free Demo key (the default when a key is present) or `pro` for a paid Pro key. Demo keys use `https://api.coingecko.com/api/v3` with the `x-cg-demo-api-key` header; Pro keys use `https://pro-api.coingecko.com/api/v3` with `x-cg-pro-api-key`. Leave both variables unset to use CoinGecko's keyless public API, which is rate-limited and intended for light use. Do not set the key to the literal word `optional`.

Server-side requests retry once through the keyless public endpoint when CoinGecko rejects the configured key with `401` or `403`; rate-limit and upstream-server errors are not duplicated.

When moving `blocklens.somto.xyz` between providers, keep the same paths (`/api/analyze`, `/api/telegram/webhook`, and `/api/telegram/coins`). Update the domain’s DNS/custom-domain attachment to the active deployment. The Telegram webhook URL can remain `https://blocklens.somto.xyz/api/telegram/webhook` as long as that route exists on whichever provider is active.

## Telegram bot setup

The bot uses a webhook, so it works with Vercel serverless functions without a long-running polling process. Create a bot with BotFather, then add these server-only variables to the deployment:

```env
TELEGRAM_BOT_TOKEN=your-bot-token
TELEGRAM_WEBHOOK_SECRET=a-long-random-secret
```

Register the webhook once through the Telegram Bot API, replacing the placeholders with your values:

```text
https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/setWebhook?url=https://<your-domain>/api/telegram/webhook&secret_token=<TELEGRAM_WEBHOOK_SECRET>
```

Users can then send `/ai-analysis` or the menu-safe `/ai_analysis` alias. The bot reads the same top-100 CoinGecko snapshot as the website, shows 12 coins per page, and runs the existing server-side Gemini analyzer after a coin is selected. The public list endpoint is available at `/api/telegram/coins` for operational checks. Telegram user IDs are not automatically BlockLens account IDs; account-linked history should only be added after an explicit linking flow.

## Data and privacy behavior

- CoinGecko supplies public market snapshots and history; no CoinGecko key is stored in the client.
- Signed-out watchlists, positions, paper-futures trades, history, alert rules, and display currency stay in this browser and synchronize only across tabs on the same origin. Signed-in watchlists, positions, paper-futures trades, history, and alert rules hydrate from Supabase and persist only to the user's account; they are not written to local browser storage. Display currency is session-only for signed-in users.
- Supabase's own auth session may remain in its client-managed storage so a user can stay signed in after reopening the browser; this stores authentication state, not portfolio or trading records.
- Portfolio CSV export is generated entirely in the browser.
- Alerts are not push notifications and do not run in the background after the page closes.
- Only the selected asset snapshot and sampled price/volume history are sent to the AI endpoint when the user explicitly requests a brief.
- The AI endpoint validates payload size and shape, applies a best-effort per-instance rate limit, and disables response caching.

## Routing and deployment

Client routes are defined in `src/App.tsx`. `vercel.json` preserves deep links with an SPA fallback; Vercel’s filesystem precedence keeps `/api/analyze.ts` available as a function. Configure the project as Vite with `dist` as the output directory.

Before deployment:

1. Run `npm test` and `npm run build`.
2. Add `GOOGLE_CLOUD_PROJECT` and `GOOGLE_SERVICE_ACCOUNT_JSON` as server-side environment variables if AI trading analysis should be enabled.
3. Add `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` to the deployment environment after running the migration.
4. Verify `/`, `/markets`, `/analysis`, `/watchlist`, `/history`, `/futures`, `/compare`, `/account`, an asset route, and `/api/analyze` on a preview deployment.

## Known operational limits

- CoinGecko’s public API can rate-limit frequent requests; BlockLens caches and deduplicates calls and keeps the last successful snapshot visible when refreshes fail.
- The serverless rate limiter is best-effort and instance-local. A shared rate-limit store is recommended for a high-traffic production deployment.
- Account sync is opt-in and requires the Supabase variables plus the SQL migration. Without them, the local fallback remains active.
